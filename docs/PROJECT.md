# Проект Spina Bifida

## Назначение

Проект исследует анализ УЗИ-кадров плода первого триместра на признаки, связанные со Spina Bifida. Участники: Yandex Cloud, Школа анализа данных, Благотворительный фонд «Спина бифида», НМИЦ АГП им. В.И. Кулакова. Приложение предназначено для исследования результатов специалистом; его выходы не являются диагнозом или подтверждением отсутствия патологии.

## Приложение

React-интерфейс обращается к Flask API через один origin. API управляет пользователями, изображениями, анализами и обратной связью. Отдельный worker получает задания из SQLite FIFO-очереди и выполняет ML-конвейер; SQLite работает в WAL mode. Сервисы запускаются на одной VM через Docker Compose. Публичный доступ обеспечивает Traefik; Object Storage и Yandex Cloud Postbox подключаются отдельно.

В приложении используются YOLOv8 для определения плоскости/ROI и DenseNet121 (`v1`) либо DenseNet201 (`v2`) для оценки качества и признаков патологии. Преобразования, пороги, Grad-CAM++ и контрольные суммы описаны в [ML-конвейере](rewrite/MODEL-PIPELINE.md). При подготовке публичного дерева численная логика инференса не менялась.

## Модели

Готовые веса `v1` и `v2` доступны по [публичным HTTPS-ссылкам](../deploy/rewrite/models/README.md). Материалы обучения в этот выпуск не входят.

В репозитории сохранены [ML-конвейер](rewrite/MODEL-PIPELINE.md), код загрузки и инференса, manifest десяти файлов весов и regression-тесты четырёх примеров. Эти материалы описывают использование и проверку готовых моделей.

## Состав публичного дерева

- Исходники, тесты, зависимости и установка Flask/React-приложения.
- Документация проекта, пользователя, разработки, ML, безопасности и эксплуатации.
- Ровно четыре исходных медицинских изображения в `apps/frontend/public/examples/`: `norm-axial.jpg`, `norm-sagittal.jpg`, `patology-axial.jpg`, `patology-sagittal.jpg`.
- Синтетические backend-fixtures для проверки загрузки/EXIF/ошибок, логотипы партнёров и тестовые снимки интерфейса с теми же четырьмя примерами. Это не дополнительные клинические случаи.

Обучающие и валидационные датасеты, разметка, patient/case manifests, веса и checkpoints, CSV с предсказаниями, сохранённые выводы/вложения ноутбуков, базы пользователей, журналы, backups, секреты и конфигурация действующих стендов исключены. Облачные примеры требуют настройки владельцем нового стенда.

`.gitignore` защищает типичные форматы данных и артефактов, но перед commit необходимо проверить весь staged diff: изображения и таблицы могут оказаться внутри JSON или notebook output.

Эти границы относятся к новому дереву файлов. Существующая история публичного Git-репозитория сохраняется; внутренние commits и ветки в неё не импортируются.
