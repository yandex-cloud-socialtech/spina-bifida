# Автоматическое развёртывание в Yandex Cloud

Запускайте команды из корня репозитория на macOS или Linux. Нужны Python 3.10+, Git, OpenSSH, curl и [Yandex Cloud CLI](https://yandex.cloud/ru/docs/cli/quickstart). Docker, Terraform и Python-библиотеки на вашей машине не нужны.

## 1. Один раз подготовить доступ

Подключите биллинг и создайте каталог в облаке. Проверьте свободные квоты выбранной зоны: по примеру нужны 4 vCPU, 8 GB RAM, SSD 50 GB, одна VM и публичный IP; для новой сети — также квота VPC. Создайте **сервисный аккаунт для запуска деплоя** и выдайте ему роли:

| Роль | Где | Для чего |
|---|---|---|
| `compute.editor` | каталог нового стенда | создать и удалить VM с диском |
| `vpc.admin` | каталог нового стенда | создать сеть, подсеть, security group и публичный IP |

Если используете существующую подсеть, она должна находиться в каталоге и зоне стенда. Новые IAM-аккаунты, YDB и бакеты скрипт не создаёт. У VM нет облачного сервисного аккаунта; ключ запускающего аккаунта остаётся на вашей машине.

Создайте и скачайте авторизованный JSON-ключ этого аккаунта. Настройте отдельный профиль CLI:

```bash
chmod 600 /path/to/deploy-sa-key.json
yc config profile create sb-deploy
yc config set service-account-key /path/to/deploy-sa-key.json
```

## 2. Заполнить три значения

```bash
cp deploy/rewrite/yc/config.example.json deploy/rewrite/yc/config.json
```

В `config.json` замените `YOUR_FOLDER_ID` на идентификатор вашего каталога, задайте уникальное имя стенда `name` и `admin_email`. Пример использует зону `ru-central1-d`, 4 vCPU, 8 GB RAM и SSD 50 GB. Ресурсы оплачиваются в вашем облаке.

По умолчанию обе версии скачиваются по [публичным HTTPS-ссылкам](../../deploy/rewrite/models/README.md). Для своего бакета задайте `models_bucket` и, если нужно, `models_prefix`. В этом случае запускающему аккаунту нужна роль `storage.viewer` в каталоге бакета. SHA-256 проверяется в обоих режимах.

Если профиль `sb-deploy` не выбран активным, добавьте `"yc_profile": "sb-deploy"`. При необходимости измените размер VM, `ssh_cidr` или укажите `subnet_id` существующей подсети. При исчерпанной квоте сетей используйте существующую подсеть в выбранной зоне. Проверьте доступность зоны и квоты перед запуском.

## 3. Проверить план и запустить

```bash
python3 deploy/rewrite/yc/deploy.py plan --config deploy/rewrite/yc/config.json
python3 deploy/rewrite/yc/deploy.py apply --config deploy/rewrite/yc/config.json
```

Исходники берутся из коммита `HEAD`; незакоммиченные правки не разворачиваются. Повторный запуск использует ранее записанный commit.

`plan` ничего не создаёт. `apply` скачает и проверит модели и CPU wheels, создаст ресурсы, установит Docker, соберёт приложение, выполнит миграции, создаст администратора и проверит реальные анализы на `v1`/`v2`. В конце напечатает адрес `http://IP` и SSH-команду.

Установка на VM выполняется через systemd. Сетевой обрыв на вашей машине её не останавливает: повторите `apply`. Существующая VM с тем же именем, но без метки этого деплоя, не используется. Состояние и SSH-ключ хранятся рядом с конфигурацией в `.state/<name>/`; сохраните этот каталог, он нужен для управления стендом. Не публикуйте его и JSON-ключ аккаунта.

## 4. Войти и добавить пользователей

Подключитесь по напечатанной SSH-команде. Реквизиты первого администратора находятся на VM в `/etc/spina-bifida/admin.json` (`root`, `0600`); прочитайте их через `sudo`. Войдите в приложение, примите условия и создайте пользователей на странице `/admin`.

По IP используется HTTP. Для HTTPS добавьте в конфигурацию `domain` и `acme_email`, направьте DNS A домена на IP VM и повторите `apply`. Если HTTP-01 Let's Encrypt недоступен, укажите также `certificate_dir` — локальный каталог с `fullchain.pem` и `privkey.pem`. Сертификат будет передан только Traefik. [Выпуск и продление ручного сертификата](OPERATIONS.md#ручной-сертификат-через-dns-01).

## Управление

```bash
# Состояние приложения / последние 100 строк установки
python3 deploy/rewrite/yc/deploy.py status --config deploy/rewrite/yc/config.json
python3 deploy/rewrite/yc/deploy.py logs --config deploy/rewrite/yc/config.json

# Удалить созданные ресурсы вместе с данными VM — подставьте точное name
python3 deploy/rewrite/yc/deploy.py destroy --config deploy/rewrite/yc/config.json --confirm sb-new
```

При ошибке ресурсы сохраняются для диагностики. `destroy` удаляет только ресурсы с меткой этого деплоя, включая автоматически удаляемый загрузочный диск; существующая подсеть и бакет моделей сохраняются. Сначала сделайте нужные [backup](OPERATIONS.md#9-резервное-копирование-и-восстановление).

По умолчанию используются проверенные на demo зеркала Яндекса для Python/Debian, Timeweb для остальных образов и npmmirror для npm. CPU wheels загружаются на запускающей машине с официального CDN и проверяются по SHA-256. Если конкретное зеркало недоступно, его можно заменить через `build_env` в конфигурации и повторить `apply`. Изменение VM-параметров или версии приложения не выполняет скрытую пересборку инфраструктуры: для нового стенда используйте новое `name`; для обновления приложения — [штатный installer](OPERATIONS.md#10-обновление-и-перезапуск).
