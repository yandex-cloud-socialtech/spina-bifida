# Безопасность rewrite

## Данные и медицинские ограничения

- Сервис не ведёт карточки пациентов и не требует идентификаторов.
- Запрещено загружать ФИО, даты рождения, контакты, номера документов/историй болезни и иные ПДн.
- Исходники и производные файлы хранятся локально по заданной retention-политике; feedback может продлевать хранение только явно предусмотренных assets.
- Логи содержат технические metadata (`app_version`, `session_id`, `language`), но не содержимое кадров и ПДн пациента.

## Учётные записи и сессии

Самостоятельная регистрация требует подтверждения почты и одобрения администратора. До этого учётная запись имеет статус `pending_email` или `pending` и не получает сессию. Решение администратора переводит её в `active` или `rejected`; обычная разблокировка не заменяет модерацию. Администратор также может создавать активные аккаунты напрямую и передавать пароль по защищённому каналу. Пароли хешируются Argon2 и никогда не возвращаются API. Cookie имеет `HttpOnly`, `SameSite=Lax`, а в domain/HTTPS mode — `Secure`. Все изменяющие запросы требуют CSRF-токен.

После увольнения или компрометации учётную запись блокируют в `/admin`. Нельзя блокировать собственную учётную запись, а также блокировать, удалять или понижать роль последнего активного администратора.

## Секреты

- `.env` создаётся с `0600`, каталог состояния/backup — с `0700`.
- `APP_SESSION_SECRET` генерируется из 48 случайных байт и не печатается.
- Ключи Object Storage находятся только в `.env`; их нельзя передавать в URL, аргументах процесса, логах или Git.
- Release archive не содержит `.env`, credentials и `.pt`.
- Backup содержит секреты и поэтому должен храниться как чувствительный зашифрованный артефакт с ограниченным доступом.

## Сеть и контейнеры

Публичные порты — только TCP 80/443 Traefik. API, frontend, worker и SQLite доступны лишь в private bridge network/volumes. Docker socket не монтируется. Контейнеры приложения работают непривилегированно, с read-only root filesystem, отдельными writable volumes и `tmpfs`.

IP mode передаёт cookie по HTTP и подходит только для изолированного тестового контура. Для рабочих данных используйте domain mode с Let's Encrypt, сетевой ACL и ограниченным административным SSH.

Docker daemon привилегирован: installer намеренно не добавляет обычного пользователя в группу `docker`. Операционные команды выполняются через `sudo`.

## Supply chain и обновления

Release bundle проверяется по SHA-256. В pull-mode все application images обязаны быть закреплены digest `@sha256:`; неприкреплённая ссылка отклоняется. Docker и NVIDIA Toolkit устанавливаются только из официальных apt-репозиториев. Модели проверяются по version-controlled manifest до запуска worker.

## Реагирование

При подозрении на компрометацию: ограничьте 80/443, сохраните защищённый backup и логи, смените `APP_SESSION_SECRET` и Object Storage keys, пересоздайте затронутые аккаунты, затем перезапустите Compose. Не публикуйте backup или логи в issue/чат без проверки на чувствительные данные.

## Письма и смена пароля

Транзакционные письма отправляются через Yandex Cloud Postbox (SESv2 over HTTPS). Ключ отдельного аккаунта с ролью `postbox.sender` хранится в защищённом env-файле; YAML содержит только отправителя, endpoint, регион и фиксированный HTTPS origin. Письма подтверждения и сброса содержат текст на русском и английском.

Случайные токены длиной 32 байта хранятся в БД только как SHA-256, действуют 24 часа для подтверждения почты и 30 минут для сброса пароля и потребляются атомарно один раз. Токен передаётся во fragment ссылки, поэтому не попадает в URL серверных access-логов; интерфейс удаляет fragment из адресной строки и требует явного нажатия кнопки. Повторное письмо заменяет предыдущую ссылку. Повторная неподтверждённая регистрация связывает новую ссылку с новым паролем; пароль первоначальной чужой заявки не сохраняется.

Сброс доступен только активным аккаунтам. Неизвестный адрес и неподходящий статус получают одинаковый ответ; сброс не меняет статус модерации. Смена пароля из профиля требует текущего пароля. После сброса/смены увеличивается версия пароля, все сессии и ранее выданные ссылки отзываются. Старые сессии существующих аккаунтов сохраняются до первой смены пароля. Длина нового пароля — 12–256 символов.

Каждый изменяющий запрос, включая публичные формы, требует CSRF. Отправка ограничена тремя запросами в час на нормализованный адрес и десятью в час на IP для каждого сценария; проверка/сброс ссылок также ограничены. API доверяет одному прокси Traefik для `X-Forwarded-For`; порт API запрещено публиковать напрямую. Лимиты хранятся в памяти одного API-процесса и сбрасываются при его перезапуске. Ошибки провайдера не логируются с содержимым писем, адресами и токенами.
